# 2026-08-25 T=40 脉冲编码生成与 LTspice-Python 三方验证日志

## 1. 工作目标

本轮工作完成了 NinaPro DB5 Exercise A 滑动窗口数据的脉冲编码流程，并对已生成的 `T=40` 数据进行了三方验证：

1. 使用最终确定的 V3 映射，将原始肌电窗口转换为输入电压 `Vin`。
2. 将 `Vin` 输入 Python 神经形态电路模型，生成分箱脉冲数据。
3. 将完整结果压缩为 ZIP，便于上传至 GitHub 和在远程平台、本地之间传输。
4. 使用 LTspice 电路、Python 电路模型和已保存的 `T_40` 数据，对随机抽取的动作窗口与通道进行交叉验证。

本日志记录实现约定、数据格式、远程运行结果、验证方法、定量结果和已知差异，便于后续复现实验。

## 2. 运行环境与实现约定

### 2.1 远程编码环境

完整脉冲编码在远程机器上运行，主要配置如下：

- Python 3.12
- NumPy 2.3.2
- Numba 0.67.0
- 25 vCPU，编码时最多使用 25 个 Numba CPU 线程
- NVIDIA RTX 5090 32 GB 未参与本次编码
- 内存 120 GB

编码采用 CPU Numba 并行实现，以便与原始 Python 电路模型保持一致。Notebook 提供 `tqdm` 进度条、分批处理、检查点和断点续跑能力，默认批大小为 128。

### 2.2 时间与分箱定义

- 每个肌电滑动窗口持续 `0.2 s`。
- 原始窗口包含 40 个采样点。
- 每个输入采样值保持 `4.999 ms`，随后使用 `1 μs` 过渡到下一个值。
- `T` 表示输入 SNN 的脉冲时间分箱数量，不表示单个时间步持续 `T` 秒。
- 本次生成的数据使用 `T=40`，因此每个分箱宽度为 `0.2 / 40 = 5 ms`。
- 脉冲张量形状为 `(窗口数, 16, T)`。

### 2.3 V3 电压映射

V3 映射使用训练集为每个通道计算的 `p1/p99` 分位点参数，将肌电幅值映射到电压范围：

- 零点参考电压：`V0 = 1.8639 V`
- 最大输入电压：`3.7278 V`
- 超出对应通道分位点范围的值执行裁剪

训练集和测试集必须共享由训练集确定的同一组映射参数，避免测试集信息泄漏或映射标准不一致。

### 2.4 Python 脉冲判定参数

脉冲检测采用当前 `system_with_tia.py` 中的参数：

- 武装阈值：`1.55 V`
- 下降沿穿越阈值：`1.25 V`
- 不应期：`0.5 ms`

每个分箱同时保存二值脉冲和脉冲计数。二值脉冲表示该时间箱内是否至少出现一次脉冲，计数则保留同一时间箱内的实际脉冲数量。

## 3. 生成的代码与数据接口

### 3.1 编码 Notebook

编码流程位于：

- `src/neurophic_system_spike_encoding.ipynb`

主要职责：

1. 读取 `ninapro_data/processed/exerciseA/slide_window` 下的训练集和测试集。
2. 计算或加载最终 V3 映射参数并生成 `Vin`。
3. 调用 Numba 加速的 Python 电路模型生成脉冲。
4. 使用 `tqdm` 显示总体处理进度。
5. 分批保存检查点，支持中断后继续运行。
6. 输出训练集、测试集、元数据及最终 ZIP 文件。

### 3.2 数据解压 Notebook

解压流程位于：

- `src/prepare_neurophic_system_spike_data.ipynb`

该 Notebook 将编码阶段生成的 ZIP 安全解压到本地目标数据目录，并检查压缩包成员路径，避免路径穿越。它适用于从 GitHub 或远程运行环境取回数据后的本地准备过程。

### 3.3 输出目录与 NPZ 数据契约

解压后的数据目录为：

```text
ninapro_data/spikes/T_40/
├── train.npz
├── test.npz
└── metadata.json
```

每个 NPZ 文件包含：

| 键 | 类型 | 形状 | 含义 |
|---|---|---|---|
| `X` | `uint8` | `(N, 16, 40)` | 每个时间箱是否出现脉冲 |
| `spike_counts` | `uint16` | `(N, 16, 40)` | 每个时间箱内的脉冲数量 |
| `Vin` | `float32` | `(N, 16, 40)` | V3 映射后的 40 个输入电平 |
| `y` | 保留原类型 | `(N,)` | 动作标签 |
| `subject` | 保留原类型 | `(N,)` | 受试者编号 |
| `repetition` | 保留原类型 | `(N,)` | 重复次数 |
| `start_sample` | 保留原类型 | `(N,)` | 原始窗口起始采样点 |

精确的连续时间 `spike_times` 不写入最终数据，以控制数据体积。需要精确事件时刻时，可由相同 `Vin` 和电路模型重新计算。

### 7.3 分箱脉冲位置

- LTspice 与 Python 的平均 40 箱二值一致率：`99.583333%`
- LTspice 与已保存 T=40 数据的平均一致率：`99.583333%`
- 48 组中有 44 组的 40 箱模式完全一致
- 其余 4 组的一致率均为 `95%`，但三方脉冲总数仍完全相同

存在分箱位置差异的 4 组为：

| 动作 | 数据集行号 | 通道 | 三方脉冲数 |
|---|---:|---:|---:|
| 无名指屈曲 | test 8,206 | CH10 | 14 |
| 无名指屈曲 | test 8,206 | CH11 | 14 |
| 小指伸展 | test 1,460 | CH11 | 5 |
| 拇指外展 | train 15,448 | CH2 | 18 |

这些差异表现为相同数量的脉冲落入了不同时间箱，符合 LTspice 与 Python 在器件模型、平滑开关行为和数值积分上存在微小事件时刻偏差的预期。当脉冲接近 `5 ms` 分箱边界时，较小的时间偏差也可能改变所属分箱。因此该现象不表明远程编码文件损坏，但后续若对分箱边界特别敏感，应增加基于精确事件时刻与容差的验证。

## 9. 结论与边界

本轮验证支持以下结论：

1. `T=40` 远程编码数据可由当前 Python 电路模型从保存的 `Vin` 精确复现。
2. Python 模型与 LTspice 在 48 个抽样通道上的 `Vout`、`final_out` 波形高度一致。
3. 三方在所有抽样通道上的脉冲数量完全一致，40 箱二值模式的平均一致率为 `99.583333%`。
4. 4 组分箱位置差异可归因于接近分箱边界时的微小事件时刻偏差；没有观察到脉冲丢失或新增。
5. 当前验证是覆盖所有 12 个动作的分层抽样验证，并不等价于对 26,626 个窗口、16 个通道的全量 LTspice 仿真证明。

如需进一步提高验证强度，可在后续工作中增加随机种子和每个动作的窗口数，记录 LTspice 与 Python 的精确脉冲时刻并使用时间容差匹配，重点分析落在 `5 ms` 分箱边界附近的事件。

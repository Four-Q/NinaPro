# 2026-08-20 NinaPro DB5 数据管道实现日志

## 1. 工作概览

本次工作基于 `ninapro_data/processed/exerciseA/slide_window` 中已经生成的滑动窗口数据，实现了 PyTorch 训练流程的数据供给部分。**数据管道保持与具体模型解耦，可同时用于 ANN、原生 SNN，以及后续可能采用的 ANN-to-SNN 转换流程。**

本轮完成内容：

- 核查滑动窗口训练集、测试集及元数据；
- 明确训练/测试划分、归一化、输出格式和类别采样策略；
- 在 `src/data` 下实现 Dataset、Transforms 和 DataLoader 构造接口；
- 预留物理器件映射 Transform；
- 实现基于训练集统计量的逐通道 Z-score 归一化；
- 实现 Windows/Linux 自适应的 DataLoader worker 策略；
- 编写并运行数据管道自动化测试；
- 使用真实 NinaPro NPZ 数据完成端到端核验。

本阶段尚未实现 ANN/SNN 模型、损失函数或完整训练循环。

## 3. 本轮确定的数据策略

### 3.1 数据划分

本阶段不再从训练集划分验证集，只使用已有的两个集合：

- `train.npz` 用于训练；
- `test.npz` 用于最终测试。

当前只实现同一批受试者上的跨 repetition 泛化，不实现留一受试者等跨受试者划分。

已有数据在生成窗口之前先按 repetition 分离训练集和测试集，因此不会将同一次动作中相互重叠的窗口分到两个集合。

### 3.2 Dataset 输出

单个样本只返回：

```python
x, y
```

对应形状和类型：

| 数据 | 单样本 | DataLoader 批次 | 类型 |
| --- | --- | --- | --- |
| `x` | `[C, T]`，即 `[16, 40]` | `[B, C, T]` | `torch.float32` |
| `y` | 标量 | `[B]` | `torch.int64` |

这个布局不绑定某一种神经网络：

- ANN 可直接使用 `[B, C, T]`；
- 时间优先的 SNN 可在模型入口执行 `x.permute(2, 0, 1)`，得到 `[T, B, C]`；
- 数据模块不导入 SpikingJelly，避免 ANN 数据管道产生无关依赖。

### 3.3 类别不均衡

当前不做额外处理：

- 训练 DataLoader 正常随机打乱；
- 不使用过采样；
- 不使用 `WeightedRandomSampler`；
- 数据模块不生成类别权重。

如后续实验发现少数类别召回率明显偏低，再在训练策略中单独引入类别权重或采样策略。

## 4. Transform 设计

输入 Transform 的固定顺序为：

```text
原始滑动窗口
  ↓
PhysicalDeviceMapping
  ↓
ChannelwiseZScore
  ↓
模型输入
```

### 4.1 PhysicalDeviceMapping

`PhysicalDeviceMapping` 是未来物理器件映射的预留接口，当前为恒等变换：

```python
output = input
```

**它被明确放在归一化之前。未来加入真实器件映射后，归一化统计量将基于器件映射的输出计算，而不是基于映射前的原始 EMG 计算。**

为了使统计量计算和逐样本训练共用同一实现，未来的映射逻辑需要同时接受：

- 单样本 `[C, T]`；
- 批数据 `[B, C, T]`。

### 4.2 ChannelwiseZScore

归一化采用逐通道 Z-score：

\[
x' = \frac{x-\mu_c}{\sigma_c+\epsilon}
\]

其中：

- `μc` 和 `σc` 只由经过 `PhysicalDeviceMapping` 的训练数据计算；
- 统计范围为样本维和时间维，每个 EMG 通道拥有独立统计量；
- 测试集复用训练集的统计量，不会使用测试数据重新拟合；
- 默认 `epsilon` 为 `1e-6`；
- 统计过程采用分块处理和 `float64` 累加，最终保存为 `float32`。

归一化 Transform 提供 `state_dict()`，统计量可以随模型检查点保存；也可以在重新创建数据管道时通过 `normalization_state` 传入，保证推理阶段使用相同参数。

需要注意：**Z-score 的目标是使训练数据每个通道的均值约为 0、标准差约为 1，不会把数值严格限制在 `[-1, 1]`。如果未来的脉冲编码器或物理器件要求有界输入，应另行采用 Min-Max 缩放或裁剪，而不能依赖 Z-score 提供范围约束。**

### 4.3 Transform 组合器

项目实现了不依赖 `torchvision` 的 `ComposeTransforms`，用于固定 Transform 顺序。没有使用 lambda 或局部可调用对象，从而减少 Windows 多进程 DataLoader 的序列化问题。

## 6. 跨平台策略

数据管道需要兼容当前 Windows 开发环境和未来 Linux + RTX 5090 训练环境，因此采用以下策略：

- 使用 `pathlib` 处理路径，不硬编码平台路径分隔符；
- Dataset 和 Transform 始终在 CPU 侧准备数据，不绑定 CUDA 设备；
- `pin_memory=None` 时根据 `torch.cuda.is_available()` 自动选择；
- 用户显式传入 `num_workers` 时始终使用指定值；
- Windows 默认 `num_workers=0`，避免 spawn、入口保护和数据复制问题；
- Linux 优先读取进程 CPU affinity，以实际可用核心数为准；
- Linux 可用核心数不超过 2 时默认使用 0 个 worker；
- Linux 核心数较多时默认使用一半核心，最多使用 8 个 worker；
- 多 worker 时自动启用 `persistent_workers`；
- 训练与测试 DataLoader 使用独立、可复现的随机数生成器。

Linux worker 数量是根据核心数给出的保守默认值，而不是对所有硬件都绝对最优。实际训练时仍可根据 GPU 利用率、存储速度和 CPU 负载显式调节。

## 7. 使用示例

完整数据管道：

```python
from src.data import create_data_pipeline

pipeline = create_data_pipeline(
    "ninapro_data/processed/exerciseA/slide_window",
    batch_size=128,
)

train_loader = pipeline.train_loader
test_loader = pipeline.test_loader

# 可随模型检查点保存，用于恢复训练或推理。
normalization_state = pipeline.normalization_state_dict()

for x, y in train_loader:
    # ANN 可以直接接收 [B, C, T]。
    ann_input = x

    # 时间优先的 SNN 可以在模型入口转换为 [T, B, C]。
    snn_input = x.permute(2, 0, 1)
```

恢复已经保存的归一化统计量：

```python
pipeline = create_data_pipeline(
    "ninapro_data/processed/exerciseA/slide_window",
    batch_size=128,
    normalization_state=normalization_state,
)
```

只获取两个 DataLoader：

```python
from src.data import create_dataloaders

train_loader, test_loader = create_dataloaders(
    "ninapro_data/processed/exerciseA/slide_window",
    batch_size=128,
)
```

# NinaPro DB5 Exercise A 数据集探索

> 本文聚焦当前项目实际使用的 **NinaPro DB5 Exercise A（E1）**。文中的文件数量、字段值、序列长度和窗口数量已根据本地数据核对；数据集背景参考 NinaPro 官方说明与 Zenodo 数据记录。

## 1. 数据集概览

NinaPro DB5 包含 10 名健全受试者的数据。受试者佩戴两个 Thalmic Myo 臂环，**共提供 16 个 sEMG 通道，每个臂环对应 8 个通道，采样率为 200 Hz。**

完整 DB5 包含 52 个动作和静息状态，分为三个 exercise：

1. **Exercise A：12 个基本手指动作；**
2. Exercise B：17 个等长、等张手势和基本腕部动作；
3. Exercise C：23 个抓握和功能性动作。

每个动作设计为重复 6 次。官方采集流程中，每次动作约持续 5 秒，随后静息约 3 秒。由于 `restimulus` 是经过事后动作检测修正的标签，实际提取出的动作区段长度不会严格等于 5 秒。

### 当前项目配置

| 项目 | 当前设置 |
| --- | --- |
| 使用范围 | DB5 Exercise A / E1 |
| 受试者 | S1～S10 |
| 动作类别 | 12 类，**不包含静息** |
| sEMG 通道数 | 16 |
| 采样率 | 200 Hz |
| 每个动作的重复次数 | 6 |
| 训练 repetition | **1、3、4、6** |
| 测试 repetition | **2、5** |
| 滑窗长度 | **200 ms，即 40 个采样点** |
| 滑窗步长 | **100 ms，即 20 个采样点** |

> 上述训练/测试划分是本项目采用的跨 repetition 评估方案，不是数据文件本身强制规定的唯一划分方式。

## 2. 本地目录与文件关系

```text
ninapro_data/
├── raw/
│   ├── archives/
│   │   ├── s1.zip
│   │   ├── ...
│   │   └── s10.zip
│   └── exerciseA/
│       ├── S1_E1_A1.mat
│       ├── ...
│       └── S10_E1_A1.mat
└── processed/
    └── exerciseA/
        ├── full_sequence/
        └── slide_window/
```

文件之间的关系如下：

- `archives/s1.zip` 对应受试者 S1，压缩包内包含 `S1_E1_A1.mat`、`S1_E2_A1.mat` 和 `S1_E3_A1.mat`，即该受试者的三个 exercise；
- `exerciseA/S1_E1_A1.mat` 只包含 S1 的 Exercise A 数据，并不代表 S1 的全部 DB5 数据；
- 其余受试者以相同方式对应到 `s2.zip`～`s10.zip` 和 `S2_E1_A1.mat`～`S10_E1_A1.mat`。

这些 ZIP/MAT 是官方提供的预处理、同步数据。项目中的“未滤波”应理解为：**Notebook 没有在官方 MAT 数据之上再次滤波**，而不是未经设备或官方流程处理的原始采集流。

## 3. MAT 文件结构

每个 MAT 文件中的各数组按时间同步。`N` 表示该文件的总采样点数，**不同受试者的 `N` 不同**。本地 10 个 E1 文件的 `N` 范围为 130,267～151,793。

| 字段 | 典型形状 | 含义 |
| --- | ---: | --- |
| **`emg`** | **`[N, 16]`** | **16 通道 sEMG。第 1～8 列来自靠近肘部的 Myo，第 9～16 列来自第二个 Myo** |
| `acc` | `[N, 3]` | 第一个 Myo 的三轴加速度原始信号 |
| `glove` | `[N, 22]` | CyberGlove 2 的 22 路未标定信号；与关节角度成比例，但不能直接视为已标定角度 |
| `stimulus` | `[N, 1]` | 根据屏幕动作提示得到的原始动作标签 |
| **`restimulus`** | **`[N, 1]`** | **事后使用动作检测方法修正持续区间后的动作标签** |
| `repetition` | `[N, 1]` | `stimulus` 对应的重复编号 |
| **`rerepetition`** | **`[N, 1]`** | **`restimulus` 对应的重复编号** |
| `subject` | 标量 | MAT 内记录的受试者编号 |
| `exercise` | 标量 | MAT 内记录的 exercise 编号 |
| `frequency` | 标量 | 采样率，当前文件中为 200 Hz |
| `sensor` | 字符串 | sEMG 设备名称，当前文件中为 `Double Myo` |
| `age` | 标量 | 年龄 |
| `gender` | 字符串 | `m` 表示男性，`f` 表示女性 |
| `height` | 标量 | 身高，单位为 cm |
| `weight` | 标量 | 体重，单位为 kg |
| `circumference` | 标量 | 桡肱关节高度处的前臂周长，单位为 cm |
| `laterality` | 字符串 | `r` 表示右利手，`l` 表示左利手 |

### 当前预处理真正使用的字段

动作分段和模型输入主要依赖：

```python
data = loadmat(
    mat_path,
    variable_names=["emg", "restimulus", "rerepetition"],
)
```

- `emg`：模型输入；
- `restimulus`：确定动作类别和动作边界；
- `rerepetition`：确定重复编号和训练/测试集合。

受试者编号由文件名和外部循环中的 `subject_id` 确定，而不是直接依赖 MAT 的 `subject` 字段。

### 本地数据中的元数据异常

对当前下载的官方压缩包进行 MD5 和字段核对后发现：

- `S2_E1_A1.mat` 的内部 `subject` 字段为 `11`，而文件名和官方受试者表均表明它是 S2；
- 10 个 `S*_E1_A1.mat` 的内部 `exercise` 字段均为 `3`，与文件名中的 E1 不一致。

因此，本项目应继续以 ZIP/MAT 文件名和明确的 E1 配置确定受试者及 exercise，不要仅凭这两个内部标量进行索引。这不影响 `emg`、`restimulus` 和 `rerepetition` 的使用。

## 5. 数据划分与评估含义

当前项目采用：

```text
训练集：repetition 1、3、4、6
测试集：repetition 2、5
```

**必须先按 repetition 确定训练集和测试集，再分别生成窗口：**

```text
MAT 数据
  ↓
使用 restimulus / rerepetition 找出连续动作区段
  ↓
按 repetition 划分 Train / Test
  ↓
分别在各自区段内部生成窗口
```

如果先切窗、再随机划分窗口，相互高度重叠的相邻窗口可能同时进入训练集和测试集，从而造成严重的数据泄漏和过高的测试准确率。

### 该划分能说明什么

训练集和测试集包含相同的 10 名受试者，只是 repetition 不同。因此它衡量的是**跨重复/跨试次泛化能力**，不能直接代表对从未见过的新受试者的泛化能力。

如果研究目标是跨受试者泛化，应改用按受试者划分的方案，例如 leave-one-subject-out（LOSO）。此外，任何标准化参数都只能在训练集上拟合，然后应用到测试集。

## 6. 完整序列与滑动窗口

两种表示方式都可以使用，选择取决于模型和实验目标，并非完整序列一定不合适。

| 表示方式 | 优点 | 局限 |
| --- | --- | --- |
| 完整动作序列 | 保留整个动作的时间结构；适合支持变长输入的 RNN、Transformer 或带掩码模型 | **序列长度不同；批处理需要 padding/packing；样本数较少** |
| 固定长度窗口 | 输入尺寸固定；容易批处理；适合 CNN、常规 SNN 等模型 | 相邻窗口高度相关；窗口级样本数不能视为同等数量的独立动作试次 |

### 完整序列的本地统计

每名受试者有 12 个动作、每个动作 6 次重复，因此共得到：

```text
总序列数：10 × 12 × 6 = 720
训练序列数：10 × 12 × 4 = 480
测试序列数：10 × 12 × 2 = 240
```

当前本地输出中，完整动作序列长度为 422～2,779 个采样点，中位数为 736 个采样点；按 200 Hz 换算约为 2.11～13.90 秒，中位数约为 3.68 秒。

### 滑动窗口的计算

当前设置为：

```text
窗口长度 = 200 Hz × 200 ms / 1000 = 40 个采样点
窗口步长 = 200 Hz × 100 ms / 1000 = 20 个采样点
```

对于长度为 `L` 的连续动作区段，若 `L >= 40`，窗口数量为：

```text
floor((L - 40) / 20) + 1
```

每个窗口从 MAT 中的 `[40, 16]` 转置为 PyTorch 常用的 `[16, 40]`，最终数据排列为：

```text
[窗口数, 通道数, 时间点数]
```

对直接把每个采样点作为一个 SNN 时间步的实现，`T = 40`。如果后续使用分箱、重采样或脉冲编码改变时间轴，则 SNN 的实际 `T` 也会随之变化。

## 7. 当前滑窗输出

文件保存在：

```text
ninapro_data/processed/exerciseA/slide_window/
├── train.npz
├── test.npz
└── metadata.json
```

每个 NPZ 文件包含：

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `**X`** | **`float32`** | **sEMG 窗口，形状为 `[窗口数, 16, 40]**` |
| `y` | `int64` | 模型标签 0～11 |
| `subject` | `int16` | 受试者编号 1～10，由文件名/循环编号确定 |
| `repetition` | `int8` | repetition 编号 |
| `start_sample` | `int32` | 窗口在该受试者原始 E1 时间轴中的起始采样点 |

当前本地结果为：

| 集合 | `X` 形状 | repetition | 窗口数 |

| 训练集 | `[17839, 16, 40]` | 1、3、4、6 | 17,839 |
| 测试集 | `[8787, 16, 40]` | 2、5 | 8,787 |

这些 `X` 直接来自官方预处理 MAT 中的 `emg`，**Notebook 没有额外滤波、归一化或标准化。**
